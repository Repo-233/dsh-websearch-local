## 0. 一句话定位

`src/` 是**权威源码**，把原来单体的 `dist/index.js` 按**功能块**拆成了 16 个独立 ES 模块。
`dist/index.js` 是旧的**打包产物**，**不要手改 dist**；改完 `src/` 后再重新打包。

```bash
node scripts/split-src.mjs           # 从 dist 重新生成 src/（覆盖，逻辑逐字一致）
node scripts/split-src.mjs --check   # 校验 src/ 与「重新生成结果」完全一致（不一致退出码 1）
```

## 3. 核心概念（改动前必须懂）

### 3.1 引擎 = 逻辑源，路由 = 入口
`ENGINES_META` 里一个**源**只占一个引擎位（如 `github`），它下面的多条 `routes`
（`api.github.com` / `gh-proxy.com` / `cors.isteed.cc`…）是**入口**，自动按顺序回退。
**同一个源的镜像不是独立引擎** —— 所以在 `repo`/`pkg` 多源合并里不会出现「同一份仓库被几
个镜像撑成十几条」。

### 3.2 免 API Key、不烧模型 token
检索只在宿主进程里发 HTTP，**不经过任何 LLM**，所以搜索不消耗模型 token，也不用填 Key
（GitHub/Gitee 令牌是可选项，只为提高频率上限）。

### 3.3 意图自动路由（`pickOrder`）
- 命中 `PKG_INTENT`（npm/pip/cargo/maven/依赖包…）→ 先走 `pkg` 多源合并。
- 命中 `CODE_INTENT`（github/git/gitlab/开源/源码/插件…）→ 先走 `repo` 多源合并。
- 都没命中 → 按 `engineOrder` 兜底（默认 Bing → 百度 → DDG）。
- 显式指定 `engine` 时，显式优先。

### 3.4 多源合并（`compositeSearch`）
`repo`/`pkg` 是组合引擎：并行查询所有就绪成员，按**来源轮转合并**（不等同全局排序，因为跨
平台分数不可比），并做跨源 URL 去重。单个成员失败会出现在 `failures`，不会静默丢。

### 3.5 路由健康度（`routeHealth`）
失败过的入口在本会话内排到同引擎其它入口之后；**不是永久拉黑**，下次仍从第一条开始试。
关键细节：`400/401/404` 表示入口本身可用（凭据/不存在），**不算**入口不可用；只有
`403/429/5xx` 与网络层错误才算。否则一次无效 token 会把好入口排到后面（踩过坑）。

### 3.6 GitHub 镜像回退（`fetchWithMirrors`）
抓 `raw.githubusercontent.com` / `github.com` 失败时，自动换 `ghproxy.net` /
`ghfast.top` / `gh-proxy.com` 重试（大陆网络差异明显）。

## 4. 设置卡片（UI 数据面）

插件自带浏览器半边就拥有自己的卡片，三件套：
1. `settings` 命名空间（`apply` 里 `settings.register('websearch-direct', Config)`）；
2. HTTP 数据面 `GET/POST /dsh-websearch-direct/api/config`、`POST /api/reset`；
3. 浏览器半边 `client/client.js` 认领 `settings.plugin.item` 槽位。

配置持久化在 `<DSH_HOME>/storages/websearch-direct/ui-config.json`，与 Cordis 配置解耦，
卡片是该文件唯一写者。数据模型版本 `UI_MODEL_VERSION = 3`（含自定义源的启停状态按数组位置
定位，避免删除代理后 label 重排导致状态错位）。

## 5. 拆分时的特殊处理（改代码前必读）

1. **`export const/function` 下放**：dist 里 `name`/`inject`/`SETTINGS_NAMESPACE`、
   `Config`、`apply` 是内联导出；拆开后改成普通声明，由各模块底部 `export { … }` 统一导出，
   `index.js` 再汇总 —— 公共形状与 dist 完全一致。
2. **`customEngineIdsFor` 归 `engines-meta`**：它只是枚举 `ENGINES_META` 的键，被
   `registry.membersOf` 与 `ui-settings.uiSnapshot` 两处使用，放 meta 层避免与设置页成环。
3. **`installCustomEngines` / `syncUiRoutes` 归 `ui-settings`**：本质是「把设置状态写进运行时
   引擎表」，与卡片状态同模块；它们改的是 `engines-meta`/`registry` 导出的**同一份对象**
   （引用共享），行为与单体时代一致。`net.js` 额外收纳了原 utils 段的 `const UA = UA_BROWSER`
   （request 默认 UA）。

## 6. 既有核心约束（来自 dist 顶部注释，改动别破坏）

- **schema 降级语义**：未装 `@deepseek-ai/schemastery` 时 `Config` 导出 `undefined`，而不是一个
  普通对象 —— 否则 Cordis 会对它做 `.validate` 具名调用导致整棵插件树崩溃。
- **代理双坑**（`net.js`）：`ProxyAgent` 的 `fetch` 可能因裸 `import('undici')` 在 junction 安装
  下解析失败；且跨 undici 实例的 `ProxyAgent` 无法交给全局 `fetch`（`TypeError: fetch failed`）。
  所以 agent 与 fetch 必须来自同一个 undici 实例。
- **工具结果要无损 JSON**：工具 execute 返回不要带 `undefined` 字段（`: undefined` 会被
  stringify 丢掉，导致宿主工具结果边界拒绝）。用条件展开，绝不用 `: undefined`。

## 7. 修改 → 打包 → 回归 流程

```bash
# 1) 只改 src/xxx.js，不要改 dist/
# 2) 校验拆分一致性（不改变文件时用 --check）
node scripts/split-src.mjs --check
# 3) 回归：离线（形状 + 错误路径）/
node scripts/check-parity.mjs
#    联网（真实搜索，对比 dist 与 src 结果是否一致）
node scripts/check-parity.mjs --live
# 4) 选中某个查询联网冒烟（可指定 engine）
node scripts/live-smoke.mjs ./src/index.js "npm http client"
# 5) 验证通过后，重新打包 dist（如已装 esbuild）
npx esbuild src/index.js --bundle --format=esm --platform=node --target=node22 \
  --outfile=dist/index.js --log-level=warning
```

> 回归基线（2026-10-18）：`--check` 一致；离线 + 联网（web / pkg 多源 / 显式 github）全部 PASS；
> `pkg` 多源合并在 src 上的结果与 dist 一致（npm/crates/Packagist/NuGet…轮转合并）。
